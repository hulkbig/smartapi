# SmartAPI 1.1.0 — Sessions 与请求解释 / Sessions and request explanations

新增 Sessions：按有可靠证据的调用方会话查看请求时间线、成功与恢复情况、用量、成本和时延统计。Sessions、Requests 与 Providers 共用路由解释图，展示请求当时的全部候选连接、条件、实际激活路径与恢复过程，支持回放、单步和减少动效。

Sessions groups requests by verified caller and conversation evidence, with timelines and scoped outcome, recovery, usage, cost and latency statistics. Sessions, Requests and Providers share a routing explanation showing the recorded candidates, conditions, actual connection and recovery, with playback, stepping and reduced motion.

## 摘要与数据 / Content and data

Request / Response 前缀可在 Settings 单独开启；默认仅采集元数据。开启后只采集新请求的有限用户可见输入与已交付输出，各最多 160 个 Unicode 字符。重复输入有响应时优先显示 Response。摘要不采集隐藏推理、system/developer 内容或工具参数；自然语言仍可能包含敏感内容，应按实际需要开启。

Request/Response excerpts are opt-in and independent of full request debug capture. New requests can retain up to 160 Unicode characters each of visible input and delivered output. Repeated input prefers the response. Hidden reasoning, system/developer content and tool arguments are excluded; visible text can still contain sensitive information.

升级增加观测表与 attempt 覆盖字段，不重算账务或补录历史正文。旧记录保留可查；新的 Session 关联从升级后的请求开始积累。缺失用量和成本显示为 unknown / partial，不视为零。

The upgrade adds observation tables and attempt coverage fields without recalculating billing or backfilling historical content. Existing history remains available; new Session associations accumulate after upgrade. Missing usage and cost remain unknown or partial.

## 安装与升级 / Install and upgrade

```sh
curl -fsSLo compose.yaml https://github.com/hulkbig/smartapi/releases/download/v1.1.0/compose.yaml
docker compose up -d --no-build
```

镜像 / Image: `bighulk/smartapi:1.1.0`, Linux AMD64 / ARM64.

沿用已有数据卷，按 [Docker 指南](../guide/docker.md)验证备份与升级。详细行为见 [Sessions 与请求解释](../session-observability.md)。

Keep the existing data volume and follow the [Docker upgrade guide](../guide/docker.en.md). See [Sessions and request explanations](../session-observability.en.md) for behavior and limits.

## 验证范围 / Verification scope

发行门禁覆盖准确公开提交的产品、并发、秘密与依赖检查，以及两种架构的原生镜像安装、鉴权、重启、备份恢复、SBOM 和漏洞扫描。每项结果以对应 workflow 为准。本版本不把历史 Mock 性能比较声明为新功能的性能数据，也不将离线测试声明为所有上游厂商实测。

Release acceptance is tied to the exact public commit and its CI, native-platform install/restore checks, SBOM and vulnerability scans. Historical mock benchmarks are not measurements of this feature, and offline tests do not establish support for every upstream provider.
